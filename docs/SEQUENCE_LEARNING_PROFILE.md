# 순서 판단 경험을 쌓는 학습 흐름 — sequence_native_v1

작성일: 2026-11-10. 이 문서는 **현재 소스에 연결한 학습 절차와 실행 전 준비**를 설명한다. 새 5제품 학습 배치의 실제 모델 호출·성능 결과를 보고하는 문서가 아니다. 최종 실제 검증 결과는 `IMPLEMENTATION_STATUS.md`와 해당 실행의 보고서를 우선한다.

## 1. 이번에 학습한다는 뜻

학습용 조립품을 분해하면서 얻은 관측을 저장하고, 관측에서 교훈과 재사용 가능한 **순서 판단 Python 스킬**을 만든다. 다음 분해에서는 Sol이 이 자료를 보고 직접 순위를 정하거나, 등록된 스킬을 골라 순위를 얻는다.

여기서 학습은 **모델 가중치 변경이나 파인튜닝이 아니다.** 모델 밖의 메모리·교훈·Python 스킬 라이브러리에 지식을 축적하는 방식이다. 같은 부품 번호의 정답 순서를 외우거나, 과거 성공을 현재 물리검증 대신 사용하는 것도 아니다.

| 담당 | 이번 경로에서 하는 일 |
|---|---|
| Sol (`gpt-6.1-sol`) | 현재 후보 전체의 시도 순서 또는 등록된 순서 스킬을 선택한다. |
| Luna (`gpt-6-luna`) | 회차 사이에 관측을 정리한 교훈과 Python 순서 스킬 후보를 생성·수정한다. 검증 후 교훈도 갱신한다. |
| 제한 Python 실행기 | `propose(ctx)`를 실행하고, 결과가 현재 후보의 완전한 순열인지 검사한다. |
| 원래 ASAP | DFS, 자세, 6축 방향, 지지 탐색과 backtracking을 수행한다. |
| ASAP/RedMax | 부품 수준 경로·안정성을 실제로 검사한다. 로봇 파지·관절 궤적·실물 성공을 보증하지 않는다. |

원래 ASAP의 마지막 두 부품에 대한 질량·고정 베이스 규칙은 유지한다. 따라서 모든 제거 선택을 LLM이 한다고 표현하지 않는다. 기존 명시 행동/물리 복구 Python 스킬을 순서 스킬로 변환 완료했다고 주장하지도 않는다.

## 2. 제품 한 개에서 진행하는 순서

아래 절차를 학습 제품 5개에 차례로 적용한다. 각 제품의 자유 분해는 두 회차이며, 스킬 검증 회차는 별도다.

1. **첫 자유 분해, seed 0**
   - 현재까지의 학습 메모리·등록 스킬·교훈을 동결한다. 첫 제품은 빈 순서 전용 라이브러리에서 시작한다.
   - Sol이 후보 순서/등록 스킬을 자유롭게 선택한다. 하위 탐색은 원래 ASAP이 수행한다.
   - 실제 성공·실패 관측, 수락 여부, 시간, 후보 순서, 물리검사 횟수, 모델 사용량을 저장한다.
   - 전체 분해가 실패해도 관측이 남았다면 학습 자료가 될 수 있다. 성공 사례만 남기지 않는다.
2. **관측에서 초기 교훈 생성, Luna 최대 1회**
   - 누적 관측에서 제품별 성공·실패가 섞이도록 최대 24건을 구성한다. 제외된 관측도 원본에서 삭제하지 않는다.
   - 교훈에는 가설, 적용 조건, 적용하지 말아야 할 조건, 순위 판단 지침, 근거 ID와 반례 ID가 들어간다.
   - 관측이 없으면 `NO_OBSERVATIONS`로 기록하고 생성을 건너뛴다.
3. **Python 순서 스킬 생성·수정, Luna 합계 최대 2회**
   - 첫 후보를 만들고, 응답/코드 계약 오류나 실제 검증 실패가 있으면 그 결과를 다음 수정 입력으로 전달한다.
   - 두 번째 호출은 실패에 대한 새 후보 생성이다. 실패한 HTTP 요청을 자동 재전송하는 기능이 아니다.
   - 이름·설명·근거 ID와 실제 제한 Python 코드를 함께 저장한다. 거절된 응답과 후보도 보존한다.
4. **후보를 실제 물리검증, 후보당 최대 2조건**
   - 같은 제품을 seed 0과 1로 처음부터 실행한다. 모델 호출 없이 해당 후보 Python을 실행해 순위를 공급한다.
   - 이 단계는 후보의 검증이므로 후보를 직접 실행한다. 아래 두 번째 자유 분해의 스킬 선택과 구분한다.
   - 첫 조건에서 실패하면 나머지 검증을 생략할 수 있다. 해당 버전은 등록하지 않고 실패 근거를 남긴다.
   - 두 조건 모두에서 전체 연결 분해, 제한 시간 내 수락, 실행 코드·입력·결과의 연결을 확인해야 등록 단계로 간다.
5. **검증 후 교훈 갱신, Luna 최대 1회**
   - 실제 검증에서 새로 나온 관측을 제공한다. 갱신한 교훈이 새 검증 근거를 인용하는지 확인한다.
   - 생성 코드의 해시·후보 해시·검증 증명 해시·이전 교훈 해시를 연결한다. 검증 후 교훈이 유효하지 않으면 등록하지 않는다.
6. **범위를 제한한 등록 후 동결**
   - 파일을 다시 열어 해시와 실제 실행 증명을 검사한 후 등록한다. 동일 코드 중복으로 라이브러리 개수를 부풀리지 않는다.
   - 같은 제품 두 seed에서 통과한 스킬은 **그 검증 범위의 잠정 등록**이다. 다른 제품에서의 효과가 입증된 것은 아니다.
7. **두 번째 자유 분해, seed 1**
   - 첫 회차와 후보 검증에서 쌓인 경험, 유효한 갱신 교훈, 등록된 스킬을 다시 동결한다.
   - Sol이 스킬 사용 여부를 자유롭게 결정한다. 등록에 실패했다면 실패한 후보를 등록 스킬처럼 제공하지 않는다.
   - 스킬이 선택되지 않으면 `NOT_SELECTED`, 실행되면 `EXECUTED_EFFECT_UNVERIFIED`로 구분한다.
   - 다음 학습 제품으로 넘어갈 때 이전 제품에서 모은 자료를 전달한다. 학습 제품의 이전 회차 경험은 허용하되 평가 제품의 자료는 제외한다.

이 과정에서 **스킬 생성, 등록, 제공, 선택, 실행, 전체 분해, 성능 개선**은 서로 다른 결과다. 예를 들어 등록·실행에 성공해도 스킬 없는 조건보다 효율적인지는 별도 비교가 필요하다.

## 3. 무엇을 어디에 저장하는가

| 자료 | 의미와 핵심 내용 | 구현 위치 |
|---|---|---|
| 실제 관측 | 제품·입력 해시, 남은 부품, 시도 부품, 원시 ASAP 결과, PASS/UNKNOWN 등 상태, `accepted_for_transition`, `deadline_exceeded`, 소스/검증기 근거 | `orchestrator/sequence_knowledge.py`: `build_native_snapshot`, `validate_native_snapshot` |
| 학습 입력 | 누적 관측의 제한된 묶음과 포함/제외 근거. 추정 blocker·실패 원인·다른 제품 ID 대응은 사실로 채우지 않는다. | `orchestrator/sequence_learning.py`: `build_sequence_learning_packet` |
| 교훈 | 자연어 가설·적용/비적용 조건·순위 지침과 검증 가능한 근거 ID | 같은 파일: `validate_sequence_lesson`, `freeze_sequence_lessons` |
| Python 후보 | 제한 문법의 코드, 이름·설명·근거, 생성 출처, 코드/후보 해시. 아직 등록 스킬이 아니다. | 같은 파일: `make_sequence_candidate`, `execute_sequence_candidate` |
| 검증 증명 | 실제 worker 결과, 호출별 VM 입력과 출력, IPC 응답 파일, 프로그램/조건/결과 해시 | `orchestrator/sequence_learning_runtime.py`: `CandidateValidationService`; `sequence_learning.py`: `validate_sequence_registration` |
| 동결 라이브러리 | 회차 시작 전에 만든 `memory.json`, `lessons.json`, `skills.json`, `pins.json` | `tools/run_sequence_training.py`: `NativeTrainingBackend.freeze` |
| 전체 진행 기록 | 두 회차·생성 버전·검증·등록·재사용·중단 사유 | `orchestrator/sequence_training_cycle.py`: `run_training_cycle` |

순서 Python의 입력은 현재 후보·현재 제품 기하 특징·출처가 있는 메모리/교훈이며, 출력은 **현재 부품 ID의 완전한 순열과 허용된 근거 ID**다. LLM의 별도 접촉 관계 입력을 Python에도 자동 제공한다고 가정하지 않는다. 외부 파일·네트워크·시뮬레이션 상태를 직접 바꾸거나 임의의 부품을 지우는 코드가 아니다. 순열 오류, 현재에 없는 ID, 근거 없는 인용, 읽기 전용 입력 변조는 거절한다.

현재 입력은 `SequenceRankService.prepare`를 통해 구성한다. 후보 생성에 쓰는 실행 입력과 후보 검증/재사용의 VM 입력을 맞췄다. 학습 facts에는 과거 선택 부품의 실제 기하 특징을 원본에서 복사하며 없으면 null/NOT_AVAILABLE이다. 교훈 조회는 인용 근거·반례의 조건을 보존하고 전체 원본의 해시와 생략 수를 기록한다. 실제 저장00335 입력에서 교훈1개와 순서 프로그램4개가 한도 안에 제공되는 것을 재생 확인했다. 실제 모델이 이미 소비했다고 해석하지 않는다.

## 4. 학습·평가 제품과 선정 근거

출처는 공식 ASAP의 `test_assembly.zip`이다. **공식 테스트 모음 안에서 우리 실험용 학습/평가 분할을 새로 만든 것**이며, 공식 GNN 학습 데이터와 같은 분할이라고 부르지 않는다.

| 역할 | 제품 ID | 부품 수 | 선택 이유/범위 |
|---|---|---:|---|
| 학습 1 | 00561 | 5 | 작은 조립품에서 시작 |
| 학습 2 | 02628 | 7 | 후보 수 증가 |
| 학습 3 | 01289 | 9 | 중간 규모 |
| 학습 4 | 00675 | 12 | 큰 제품으로 단계 확장 |
| 학습 5 | 00365 | 15 | 이번 학습 집합의 최대 규모 |
| 향후 평가 후보 1 | 04205 | 11 | 저장소 노출 감사에서 제외된 적격 후보, 현재 메타데이터만 선정 |
| 향후 평가 후보 2 | 04084 | 13 | 동일 기준, 현재 메타데이터만 선정 |
| 개발 holdout | 00335 | 16 | 이미 GNN·LLM 실행에 사용. 새로운 제품 평가로 보고하지 않음 |

학습 제품은 정확히 5·7·9·12·15부품인 항목에서 ID 사전순으로 고른다. 먼저 선정한 학습 제품과 정규화 꼭짓점이 절반 이상 겹치는 제품은 제외하는 규칙을 먼저 정했다. 실제 선정에서 이 규칙으로 제외된 항목은 0개였다. 성공률·실행 시간을 보고 후보를 바꾸지 않는다. 입력 오류가 나면 기록하고 중단하며, 성공하는 다른 제품으로 몰래 바꾸지 않는다.

평가 후보는 10~12, 13~15부품 구간에서 기존 노출 제품과 기하 중복을 제외하고 고정 SHA256 정렬로 정했다. 감사는 3,326개 JSON과 기존 크기 제한을 넘었던 보고서 2개를 추가로 읽었고, 추적된 노출 제품 36개를 제외 근거로 삼았다. 이는 **저장소에서 추적한 노출의 감사**이며 외부 프로젝트나 모델 사전학습까지 조사했다는 뜻은 아니다.

기하 중복 검사는 평행이동·균일 축척에 불변인 부품 꼭짓점 지문을 사용한다. 임의 회전, 다른 삼각분할, 의미적으로 같은 제품까지 완전히 배제하는 검사는 아니다. 부품 수는 난도의 거친 지표일 뿐이며 실제 분해 난이도가 반드시 순서대로 증가하지 않는다.

## 6. 제안 API·물리 예산과 중단 조건

아래는 **새 유료 실행 제안**이다. 이전 한 회차의 남은 예산을 자동 전용하지 않는다. 파일의 설정이나 생성된 실행 계획만으로 유료 호출을 허용하지 않는다.

| 구분 | 최대 호출 | 프로그램 비용 상한 |
|---|---:|---:|
| Sol 자유 분해 | 회차당 25회 × 10회차 = 250회 | 회차당 $4.00, 합계 $40.00 |
| Luna 교훈·후보·후속 교훈 | 제품당 최대 4회 × 5제품 = 20회 | 제품당 $0.10, 합계 $0.50 |
| 전체 | **270회** | **$40.50** |

자동 HTTP 재시도는 0회이며 실패 회차 자동 재실행도 없다. endpoint는 `https://api.openai.com/v1/responses`다. 공식 문서에서 2026-11-10 확인한 표준 단가는 Sol 입력/출력 100만 토큰당 $2/$10, Luna $0.10/$0.50이다. 출처: [Sol 모델](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [Luna 모델](https://developers.openai.com/api/docs/models/gpt-6-luna).

본문 byte 상한·요청 여유 2,048·출력 상한으로 계산한 보수적 예약액은 Sol 250회 $38.912, Luna 20회 $0.3072, 합계 **$39.2192**다. 실제 사용 토큰이나 공급자 청구액과 같은 값이 아니다. 직전 00335의 실제 16회 사용량에 같은 단가를 적용한 값은 $0.689712였고, 그 평균을 250회에 단순 적용하면 약 $10.78이다. 제품·경험 입력·탐색이 달라지는 이번 배치의 비용 보장으로 사용하지 않는다.

| 물리 실행 | 최대 회차 | 회차당 제한 |
|---|---:|---|
| 자유 분해 | 10 | 본 60분 / 외부 65분; 복합 시도·경로·안정성 각각 256회 |
| 후보 등록 검증 | 최대 20 | 본 10분 / 외부 11분; 복합 시도·경로·안정성 각각 128회 |

후보 검증 20회는 5제품 × 후보 최대 2버전 × seed 2조건의 상한이다. 등록 실패 시 수행하지 않는 후속 단계가 있으므로 실제 호출/검증 수는 더 적을 수 있다. 각 종류의 검사 상한 합계는 최대 5,120회다.

본 실행 제한을 모두 합하면 13시간 20분, 외부 종료 제한은 **14.5시간**이다. 실제 작업시간 5~8시간은 준비·검증을 포함한 계획상 추정이며 실측 예측 모델이 아니다. 조기 완료/중단, 보고서 작성 시간 등에 따라 달라진다.

중단·거절 기준:

- source·동결 파일 변조, 제품 ID/평가 분할 불일치, 입력 계약 불일치는 진행을 허용하지 않는다.
- 불확실한 통신/HTTP/응답 계약 오류는 후속 유료 요청을 중단한다. 명확한 호출/비용 한도 소진은 해당 결과를 기록하며 배치의 처리 규칙과 구분한다.
- 실제 검증 실패는 범용 불가능 판정이 아니다. 해당 후보의 조건부 실패로 저장한다. 무근거 blocker나 충돌 원인을 만들어 넣지 않는다.
- 검증 조건 부족·전체 연결 분해 실패·증명 해시 불일치·갱신 교훈 오류가 있으면 스킬을 등록하지 않는다.
- 두 번째 자유 분해에서는 스킬 사용을 강제하지 않는다. 성공을 위해 지지·방향·물리 기준을 임의로 완화하지 않는다.
