# LLM Robot Disassembly Research

이 프로젝트는 조립된 CAD에서 검증 가능한 분해 순서를 찾는다. Astra는 현재 시도할 부품의 우선순위를 제안하고, 공식 ASAP은 DFS로 순서를 탐색한다. 각 시도의 자세·방향·지지와 경로·안정성은 ASAP과 RedMax가 검사한다. 마지막 두 부품은 원래 ASAP의 질량·고정 베이스 규칙을 따른다.

## 현재 실행 경로

| 용도 | 위치와 역할 |
|---|---|
| 기본 실행 | `tools/run_sequence_native_experiment.py`에 `--run`을 준다. `--mode prepare`는 입력 준비, `--mode fixture`는 지정 순위와 실제 물리검증, `--mode astra`는 유료 모델을 쓰는 실행이다. |
| 입력·검색·물리 연결 | [caseplanner](caseplanner)와 [기본 설정](configs/astra_cases_v1.json). Windows에서 실행하면 전용 WSL로 연결된다. |
| 새 운영 기억 | 기본 저장소는 `.cases/index.sqlite`와 그 옆의 사례별 근거 파일이다. 해결된 사건과 Astra가 작성한 짧은 해결지침을 함께 보관한다. |
| 실행 기록 | 각 `--run` 폴더에 실패·성공 검사, 이미지, 영상, 결과, 조립 전달용 `export_v1.json`을 저장한다. 조립 쪽에는 검증된 분해 경로의 역순을 후보로 전달한다. |

## 어떤 과거 자료를 활용하나

새 실행은 시작할 때 운영 사례 목록을 고정한다. 실패 후에는 같은 검사 단계와 결과를 가진 사례에서 실제 실패 이미지가 비슷한 지침을 최대 3건 찾는다. 실패한 부품이 같은 시작 상태에서 이어진 채택 경로에서 실제로 제거되고 유효한 지침이 작성돼야 새 사례를 등록할 수 있다.

11월 19일 동결본의 경험 642건·교훈 52건·스킬 카드 10건은 이전 연구 자료다. Luna·Astra가 생성한 등록 Python 스킬은 그중 2건이다. 이 자료와 당시 코드·ASAP 기준선은 당시 실험을 재현할 때 사용한다. 과거 기록을 새 이미지 검색 사례로 활용하려면 실제 실패 장면과 같은 경로의 해결 근거부터 확인해야 한다. 운영 기억과 모의 시험 기억은 별도 DB를 사용한다.

11월 22일 확인한 새 운영 기억은 0건이었다. 트레이 두 회차에서 실제 물리와 이미지 검색이 동작했고, 지침 작성과 인용에는 모의 응답을 사용했다. 실물 로봇 실행과 실제 Astra의 자율 재사용은 후속 검증 대상이다.
